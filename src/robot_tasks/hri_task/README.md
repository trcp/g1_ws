# HRI Task パッケージ概要

このパッケージは、G1ロボットにおける HRI (Human-Robot Interaction) タスク（主にゲストの出迎え、特徴の抽出、追従、案内など）を実行するための ROS2 / Python パッケージです。

## 📂 ディレクトリ構成と各コードの役割

ここでは `hri_task/hri_task` ディレクトリ内にある主要なコードの役割と、将来的な変更方法について詳しく解説します。

### 1. `main.py`
*   **役割**: HRI タスク全体の流れを管理する「大元」のファイルです。SMACH (State Machine) を用いて、「待機 → 移動 → 人を探す → 挨拶する → 案内する」といった一連の状態遷移を定義しています。
*   **変更方法**: 
    *   **タスクの順序を変えたい場合**: `sm.add('STATE_NAME', StateClass(), transitions={...})` の部分を並び替えるか、遷移先 (`success` や `failure` の値) を書き換えます。
    *   **新しい動作を追加したい場合**: 新しい State クラスやコールバック (`cb`) 関数を作成し、ステートマシンに追加します。
    *   **話す言葉（TTS）を変えたい場合**: 各ステートに渡している `message` 引数や、コールバック内の `SAY("...")` の文字列を変更します。

### 2. `yolo_states.py`
*   **役割**: YOLO（物体・人物検出）の結果を利用してロボットを動かすための「個別の状態（ステート）」を定義しています。人を追跡して腰を向ける、空いている椅子を探す、カバンを見つけるなどの具体的なアクションが書かれています。
*   **変更方法**:
    *   **追従する距離やしきい値を変えたい場合**: 各クラスの `__init__` にある `distance_threshold` や `timeout` などを調整します。
    *   **空席判定のロジックを変えたい場合**: `YoloEmptyChairState` 内の人と椅子の重なり判定（Intersection over Union など）の計算式を調整します。

### 3. `g1_config.py`
*   **役割**: ロボットの物理的な寸法、カメラの位置パラメータ、関節の角度制限、移動のしきい値などを一元管理する「設定ファイル」です。
*   **変更方法**:
    *   **実機テストで腕の届く距離がおかしい場合**: `RobotGeometry` の `L_UPPER` (肩〜肘) や `L_LOWER` (肘〜手先) などの数値を実測値に合わせて変更します。
    *   **カメラの位置や角度が実機とズレている場合**: `CameraParams` の `CAM_FROM_NECK_X` などを修正します。実機調整時は**基本的にこのファイルだけ**を書き換えることで全体に反映されるように設計されています。

### 4. `bag_grasp_ik.py`
*   **役割**: 逆運動学 (Inverse Kinematics: IK) を計算するファイルです。カメラで見つけた物体（カバンなど）の座標から、「右腕の肩と肘をそれぞれ何度曲げれば届くか」を数学的に計算します。
*   **変更方法**:
    *   **掴むときの腕の姿勢（肘の曲がり具合など）を変えたい場合**: この中の `calculate_bag_grasp_joints` や `solve_2link_ik` の数式・制限値を調整します。純粋な数学的計算のため、通常はあまり触る必要はありません。

### 5. `direct_joint_control.py`
*   **役割**: MoveIt 等の高度なプランナーを使わず、ロボットの関節（腕や腰）の目標角度を直接パブリッシュし続けるコントローラーです。バックグラウンドスレッドで一定周期（10Hz等）でパブリッシュし続けることで、重力で腕が落ちるのを防ぎ姿勢を保持します。
*   **変更方法**:
    *   **決め打ちのポーズ（初期姿勢や指差し姿勢）を変えたい場合**: ファイル上部にある `HOME_POSE` や `ARM_POSE_EXTEND_RIGHT` などの辞書に入っている各関節の角度（ラジアン）を調整します。
    *   **関節が動くスピード（滑らかさ）を変えたい場合**: `_publish_loop` 内の `max_step` の数値を調整します（数値を小さくするとゆっくり動き、大きくすると速く動きます）。

### 6. `yolo_track.py`
*   **役割**: YOLOで検出した人の方向へロボットのベース（足回り）を移動させるためのトラッカーです。EKF（拡張カルマンフィルタ）を用いて人の動きを予測しつつ、同時に LiDAR の点群情報を使って障害物を避ける（カニ歩き等）制御も行います。
*   **変更方法**:
    *   **人との維持距離を変えたい場合**: ファイル上部の `FOLLOW_DISTANCE = 0.8` (m) を変更します。
    *   **追従スピードを変えたい場合**: `LINEAR_MAX` や `ANGULAR_MAX` の数値を調整します。
    *   **障害物回避のしきい値を変えたい場合**: LiDARに関する設定値（`LIDAR_Z_MIN`, `LIDAR_X_MAX` など）を変更します。

### 7. `word_sprit.py`
*   **役割**: 音声認識などから得られた文字列の中から、特定のキーワード（名前や飲み物など）を抽出するためのユーティリティスクリプトです。
*   **変更方法**:
    *   **抽出のルールを変えたい場合**: `search_keywords` 関数の正規表現やマッチングロジックを調整します。

## 🐋 `yolo_human/` ディレクトリ (YOLO コンテナ側)

このディレクトリは、メインの ROS ノードとは別の Docker コンテナで動き、カメラ画像を処理して人を検出したり、服の特徴を抽出したりします。

### 1. `yolo_human_node.py`
*   **役割**: YOLO を用いてリアルタイムにカメラ画像から人物と物体を検出・トラッキングするノードです。必要に応じて非同期で OpenAI API を叩き、人物の服飾的特徴を取得します。
*   **変更方法**:
    *   **検出対象を増やしたい場合**: コマンドの `classes` 指定や、内部のデフォルト `target_classes` に "chair" や "bag" などを追加します。

### 2. `clothing_analyzer.py`
*   **役割**: 人の画像を元に、服の色（KMeans）や柄（CLIP）を判定するスクリプトです。OpenAI API が使えない環境（オフライン）でのフォールバックとして機能します。
*   **変更方法**:
    *   **色の分類ルールを変えたい場合**: `_COLOR_RULES` の HSV のしきい値を変更します。
    *   **柄のリストを変えたい場合**: `PATTERN_LABELS_EN` / `PATTERN_LABELS_JA` のリストを変更します。

### 3. `extract_person_features.py`
*   **役割**: OpenAI の Vision API (GPT-4o 等) を呼び出して、画像から詳細な人物の特徴（服の種類や色、眼鏡の有無など）を自然言語で抽出するスクリプトです。
*   **変更方法**:
    *   **抽出する特徴の指示を変えたい場合**: `prompt` に書かれているプロンプト文字列（AIへの指示）を書き換えます。例えば「靴の色も教えて」などと追加します。
    *   **タイムアウトやレスポンスの長さを変えたい場合**: 関数引数の `timeout` や `max_tokens` の値を変更します。

## 🚀 起動方法と開発のコツ

*   **メイン制御（WezTerm経由）**:
    WezTerm上で設定された `HriMain` や `YoloHuman` パネルから自動起動できます。
*   **YOLO側の開発時のコツ**:
    `yolo_human` 内の Python ファイル（`yolo_human_node.py` など）は `docker-compose.yml` で直接マウントされているため、**ホスト側のコードを保存してコンテナを再起動（compose down & up）するだけでそのまま反映**されます。Docker のビルドをやり直す必要はありません。
